# KioBridge 건강 추천 엔진 — 규칙셋 & 데모

> 고령자 대상 배리어프리 키오스크 보조 서비스 **KioBridge**의
> "건강 추천 엔진(Health Recommendation Engine)"에 쓰인 **질환·약물–식품 상호작용 규칙셋**과,
> 이를 실제로 적용하는 **필터링 데모 스크립트**입니다.

**2026 스타트업 영그라운드 MVP 개발 해커톤** · 팀 그랜토리

## 프로젝트 개요 · 내가 맡은 파트

**KioBridge**는 키오스크 앞에서 전화번호만 누르면 어르신 휴대폰(2G 폴더폰 포함)으로 전화가 걸려와,
AI 에이전트와 통화하며 주문하고 본인의 질환·복용약·알레르기에 맞는 메뉴를 추천받는 배리어프리 키오스크 보조 서비스입니다.
팀 그랜토리가 해커톤에서 서비스 전체(키오스크 화면 · 전화 주문 흐름 · 사용자 정보 등록 사이트 · 추천 엔진)를 함께 만들었습니다.

| 구분 | 담당 |
|---|---|
| **DA — 건강 추천 엔진 데이터셋 설계 · 규칙 적용 로직** | **본인** (이 저장소) |

이 저장소는 그중 **본인이 맡은 DA 파트**만 담고 있습니다.

## 이 저장소가 하는 일

키오스크 앞의 고령 사용자가 **본인의 질환·복용약·알레르기**에 맞춰
메뉴 선택 안내를 받도록 하는 것이 목표입니다.
이 저장소는 그 판단의 **근거가 되는 규칙 데이터**와, 규칙이 실제로
동작하는지 보여주는 **작은 파이썬 데모**로 구성됩니다.

엔진은 메뉴를 다섯 등급으로 나눕니다.

| 등급 | 기준 |
|---|---|
| **제외** | 알레르기 성분 포함. 후보에서 완전히 제외 |
| **주의** | 질환·약물의 제한 규칙에 해당. 사유와 대안 문구를 함께 표시 |
| **권장** | 제한 규칙에 해당하지 않고 권장 규칙에 해당 |
| **판단 보류** | 권장 규칙에 해당하지만, 확인되지 않은 조건부 제한 규칙이 함께 걸림 |
| **규칙 없음** | 입력한 질환·약 기준으로 해당 규칙이 없음. 건강에 좋다는 뜻이 아님 |

모든 사유에는 근거가 된 규칙 ID와 매칭 근거(메뉴명 키워드 또는 태그)를 함께 출력합니다.

> ⚠️ 이 프로젝트는 **의료기기가 아니며 진단·처방을 하지 않습니다.**
> 공개된 식이 가이드라인에 근거한 **'주의 안내'만** 제공합니다.

## 데이터셋 개요

원본은 22개 시트로 구성된 `data/foodcourt_dataset_v4_3.xlsx` 입니다.
질환 선정 → 식품/영양소 규칙 → 약물 상호작용 → 메뉴 매핑 → 복합질환 충돌
→ 예외 처리까지, 근거 기반으로 직접 설계했습니다.

주요 시트:

| 시트 | 내용 |
| --- | --- |
| `01_질환선정` | 65세 이상 유병률·식이개입 명확성 기준으로 8개 질환 선정 |
| `02_질환_식품규칙` | 질환별 제한/권장 식품군 + 근거수준(HIGH/MEDIUM) + 서비스 문구 |
| `07_질환_영양소규칙` | 나트륨·칼륨·퓨린 등 영양소 단위 규칙 |
| `08_약물_식품규칙` | 와파린-비타민K, 자몽-CYP3A4 등 약물–식품 상호작용 |
| `14_약물사전` | 약물군·대표성분·국내 제품명 매핑 |
| `15_메뉴사전` | 메뉴별 food_tag·연결 질환·연결 약물 |
| `16_복합질환_충돌` | 고혈압+CKD 칼륨 충돌 등, 규칙이 상충할 때의 해소 원칙 |
| `22_닭강정매핑` | 해커톤 대상 매장(chicken-store)에의 신호 매핑 |

### 질환 선정 논리 (요약)

단순히 유병률이 높은 질환이 아니라, **메뉴 수준에서 식이 개입이 명확한지**를
기준으로 골랐습니다. 예를 들어 골관절염은 노인 다빈도 질환이지만 특정 음식
하나를 "피하라"고 매핑할 근거가 약해 자동 경고에서 제외했고, 반대로 통풍은
유병률 상위 10위 밖이지만 고퓨린·알코올 제한 근거가 명확해 **보조 핵심**으로
포함했습니다.

### 복합질환 충돌 처리

여러 규칙이 상충할 수 있습니다. 대표적으로 **고혈압은 채소·과일(칼륨)을 권장**하지만
**CKD+고칼륨혈증에서는 칼륨을 제한**해야 합니다. 이 경우 검사·의료진 설정이 있을
때만 칼륨 제한을 적용하고, 없으면 자동 제한을 **보류**합니다
(`16_복합질환_충돌` 참조). "확실하지 않으면 임의로 제한하지 않는다"가 원칙입니다.

## 데모 실행

```bash
python recommend.py          # 3가지 데모 프로필의 결과 출력 (demo_output.txt)
python tests/test_engine.py  # 회귀 테스트 23개 (pytest tests/ 로도 실행 가능)
python consistency.py        # 메뉴사전과 엔진 결과의 일치 검사 (consistency_report.txt)
```

표준 라이브러리만 사용하므로 설치할 패키지가 없습니다.

핵심 동작 예시 (실제 출력은 [`demo_output.txt`](./demo_output.txt)):

- **자몽에이드** → 당뇨(가당음료) + 암로디핀(자몽–CYP3A4 상호작용) **이중 감점**
- **김치찌개·라면·설렁탕** → 고혈압 나트륨 규칙으로 주의
- **된장찌개** → 대두 알레르기로 **제외**
- **시금치나물** (와파린 복용 시) → 비타민K 주의 문구 (금지가 아니라 "양 일정 유지")
- **크랜베리주스** (와파린 복용 시) → 출혈 위험 주의
- **미역국** (갑상선약 복용 시) → 감점 없이 복용 시간 간격 안내만 표시
- **시금치나물** (고혈압+CKD, 검사 미확인) → 채소 권장 규칙에 해당하지만 칼륨 조건부 규칙이 걸려 **판단 보류**
- **삼겹살·후라이드치킨** (고혈압+당뇨) → 해당 규칙이 없어 **규칙 없음**으로 분리 (권장 목록에 넣지 않음)

프로필을 바꿔 보려면:

```python
from recommend import Profile, print_report

print_report(Profile(
    diseases=["통풍", "이상지질혈증"],
    drug_ids=["RX001"],        # 와파린
    allergen_tags=["SOY"],     # 대두
    ckd_lab_confirmed=False,   # CKD 조건부 규칙 on/off
))
```

### 규칙 매칭 방식

규칙 하나가 메뉴에 해당하는지는 두 단계로 판정합니다.

1. **메뉴명 키워드**: 규칙의 `푸드코트 키워드 예시`가 메뉴명에 들어 있으면 매칭.
   한 글자 키워드(국, 탕, 죽 등)는 메뉴명 단어의 끝 글자일 때만 인정합니다(`국`이 `국수`에 걸리지 않도록).
2. **태그**: [`data/rule_tag_map.json`](./data/rule_tag_map.json)에 규칙 ID별로 적어 둔 `food_tag`가 메뉴 태그에 있으면 매칭.
   규칙의 식품군과 태그의 범위가 같을 때만 연결했습니다. 예를 들어 `가공육` 규칙에 `PROCESSED`(가공식품 전반)를 연결하면
   김치찌개까지 걸리므로 연결하지 않았습니다.

### 점수 로직

점수는 등급 안에서의 정렬과 설명을 위한 데모용 값입니다.

- 기본 10점에서 시작
- 질환 제한 규칙: 근거수준 HIGH −5 / MEDIUM −3 (**질환당 1개만 반영**)
- 질환 권장 규칙: HIGH +3 / MEDIUM +2 (질환당 1개만 반영)
- 약물 제한 규칙: HIGH −6 / MEDIUM −3 (**약당 1개만 반영**)
- 약물 CONTROL 규칙(복용 시간 조절): 감점 없이 안내만 표시
- CKD 조건부 제한은 검사·의료진 확인(`ckd_lab_confirmed=True`)이 있을 때만 적용
- 한 질환에서 여러 규칙이 걸리면 영향이 큰 규칙, 같으면 메뉴명 키워드로 걸린 규칙을 대표로 선택

## v2 → v3 수정 내역

v2 데모 출력을 검토하다가 결과가 잘못된 곳을 발견해 매칭 로직을 다시 작성했습니다.

| v2의 문제 | 원인 | v3의 수정 |
|---|---|---|
| 김치찌개·라면·미역국 등 **국물 메뉴 전부에 "시럽이나 설탕을 빼고 주문할까요?"** 가 붙음 | 규칙 설명문에 `탕`이 있으면 국물 태그로 연결했는데, 설탕 규칙의 "설**탕**"에도 해당 | 글자 포함 검사를 없애고 규칙 ID별 태그를 명시(`rule_tag_map.json`) |
| 고혈압+당뇨 프로필에 **삼겹살·곱창·후라이드치킨·제육덮밥이 "안심하고 고르기 좋은 순" 1~5위** | 걸린 규칙이 없으면 기본 점수 그대로 최상위에 정렬 | "규칙 없음" 등급을 분리. 권장 등급은 권장 규칙에 해당할 때만 부여 |
| 고혈압+CKD(검사 미확인)에 **칼륨이 많은 시금치나물을 권장** | 조건부 제한을 보류하면 권장 규칙만 남음 | 조건부 규칙이 보류된 메뉴는 "판단 보류"로 분리 |
| 크랜베리주스–와파린, 된장찌개–항우울제 등 **약물 규칙 누락** | 약물 규칙의 태그 이름이 메뉴사전의 태그 이름과 다름 | 약물 규칙도 메뉴명 키워드로 매칭, 필요한 태그 연결 추가 |
| 복용 시간 조절 규칙(CONTROL)이 제한 규칙과 같은 크기로 감점 | action 값을 구분하지 않음 | 감점 없이 안내만 표시 |
| 메뉴사전에 "관련 질환"으로 적힌 조합이 엔진에서 걸리지 않아도 알 수 없음 | 검증 절차 없음 | 일치 검사(`consistency.py`)와 회귀 테스트 추가 |

### 메뉴사전과 엔진의 일치 검사

메뉴사전에는 설계 단계에서 사람이 적은 `관련 질환 규칙`, `관련 약물 규칙` 열이 있습니다.
엔진이 실제로 그 조합에 규칙을 적용하는지 전수 비교했습니다([`consistency_report.txt`](./consistency_report.txt)).

| | 사전의 쌍 | 걸리지 않는 쌍 (v3) | 문헌 근거 보완 후 |
|---|---|---|---|
| (메뉴, 질환) | 50 | 5 | **2** |
| (메뉴, 약) | 21 → 27 (통풍약 추가) | 3 + 통풍약 6건은 약물사전에 없어 검사 불가 | **6** |

남은 8건은 문헌을 검토한 뒤 **규칙을 만들지 않기로 한 조합**입니다(아래 표).

## 문헌 근거 보완 (v3.1 ~ v3.2)

일치 검사에서 드러난 누락과 기존 약물 규칙을 문헌으로 다시 검토하고, 문헌에서 근거가 확인되는 규칙을 추가했습니다.
원본 데이터셋은 수정하지 않고, 추가·수정 내용을 [`data/rules_supplement.json`](./data/rules_supplement.json)에,
근거 문헌 27건을 [`data/evidence_sources.json`](./data/evidence_sources.json)에 분리해 두었습니다.

### 근거수준을 정한 기준

근거수준은 **문헌의 연구설계만으로** 정했습니다. 메뉴 판정의 불확실성(태그가 "가능" 수준인 경우 등)은 근거수준에 섞지 않고 규칙의 `조건/예외`에 따로 적었습니다.

| 근거수준 | 해당하는 근거 | 점수 반영 |
|---|---|---|
| **HIGH** | 무작위 시험과 그 메타분석, 의약품 허가사항·규제기관 안내, 진료지침의 강한 권고(Class I) | 질환 −5, 약물 −6 |
| **MEDIUM** | 관찰 연구(코호트)와 그 메타분석, 조건부 권고, 전문가 합의, 소규모 약동학 연구, 증례 보고, 서술적 종설 | −3 |

관찰 연구는 대상자가 많아도 MEDIUM입니다. 연관성은 보여 주지만 인과관계를 확정하지 못하기 때문입니다.
증례 보고는 결과가 심각해도(예: 고혈압 위기) 근거의 무게는 MEDIUM으로 두고, 심각성은 `조건/예외`에 적었습니다.
이 기준이 지켜지는지는 테스트(`test_evidence_level_follows_study_design`)로 검사합니다.

### 추가한 질환 규칙

| 규칙 | 대상 | 근거수준 | 근거 문헌 | 연구설계와 핵심 수치 | 적용 조건·한계 |
|---|---|---|---|---|---|
| R033 | 당뇨병 – 튀김류 | MEDIUM | Cahill 2014, *Am J Clin Nutr* | 전향적 코호트 2개. 주 7회 이상 섭취 시 당뇨병 발생 RR 1.55 | 발생 위험 연구. BMI 등을 보정하면 연관성이 약해짐 |

### 규칙을 만들지 않은 조합

| 조합 | 이유 |
|---|---|
| 미역국 – 통풍 | 통풍 위험을 높인 것은 육류와 해산물이었고 퓨린이 많은 채소는 관련이 없었음(Choi 2004, *NEJM*). 해조류를 직접 다룬 근거는 찾지 못함. 근거 없이 만들면 과잉 경고 |
| 초밥 – 고혈압(간장), 비빔밥 – 와파린(나물) | 규칙은 이미 있음. 간장과 나물 종류가 선택 사항이라 메뉴 단위로는 판정할 수 없음. 옵션 단위 데이터가 필요 |
| 설렁탕·삼겹살·곱창·짬뽕·미역국 – 통풍약 | 고퓨린 식품 제한은 약물 상호작용이 아니라 통풍 질환의 식이 권고. 질환 규칙(R022~R024)이 담당 |

### 문헌 확인 범위

- 문헌은 **PubMed 초록과 검색 요약으로 확인**했고 전문을 읽은 것은 아닙니다. 문헌마다 확인한 범위를 `evidence_sources.json`의 `확인수준`에 적었습니다.
- 서지사항(저자, 권·쪽수, PMID)을 확인하지 못한 문헌은 비워 두거나 "확인 필요"로 표시했습니다.
- 자몽 상호작용의 약물별 위험도 표(Bailey 2013, *CMAJ*)는 열람하지 못했습니다. 스타틴 중 로수바스타틴이 해당하지 않는다는 내용은 2차 자료로만 확인했습니다.
- 원본 약물 규칙 17개 중 문헌으로 재검토한 것은 DR002, DR003, DR004, DR005, DR008 다섯 개입니다. 나머지 12개는 원본 그대로이며 검토하지 않았습니다.
- 원본 질환 규칙 32개는 문헌으로 재검토하지 않았습니다.
- 원본 xlsx에는 보완 내용을 아직 반영하지 않았습니다.

## 한계 및 참고

- **"규칙 없음"은 안전하다는 뜻이 아닙니다.** 규칙 데이터가 다루는 질환 7개·약물군 18개 범위 안에서만 판단합니다.
  규칙에 없는 조합은 판단하지 못합니다.
- **메뉴 태그는 메뉴 28개에 대해 사람이 붙인 값**입니다. 실제 서비스에서는 매장별 레시피·영양성분과 옵션(소스 적게, 국물 적게)을 반영해야 합니다.
- **메뉴 하나 단위로만 판단합니다.** 밥+면 같은 조합 규칙(R010)과 추가 옵션 규칙(R030)은 적용하지 않습니다.
- **`rule_tag_map.json`의 규칙–태그 연결은 본인이 규칙 본문을 읽고 정한 값**이며 영양사·약사의 검수를 거치지 않았습니다.
- 점수·가중치는 데모용 값입니다. 실제 서비스에서는 질환·약물별 임상 우선순위에 따라 재보정이 필요합니다.
- 이 저장소에는 해커톤 주최 측이 제공한 시뮬레이터 킷·창업팀 배포 자료는
  포함하지 않으며, **직접 설계한 데이터셋과 적용 로직만** 담았습니다.
