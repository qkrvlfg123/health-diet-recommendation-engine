# KioBridge 건강 추천 엔진 — 규칙셋 & 데모

> 고령자 대상 배리어프리 키오스크 보조 서비스 **KioBridge**의
> "건강 추천 엔진(Health Recommendation Engine)"에 쓰인 **질환·약물–식품 상호작용 규칙셋**과,
> 이를 실제로 적용하는 **필터링 데모 스크립트**입니다.

**2026 스타트업 영그라운드 MVP 개발 해커톤** · 팀 그랜토리

## 프로젝트 개요 · 내가 맡은 파트

**KioBridge**는 키오스크 앞에서 전화번호만 누르면 어르신 휴대폰(2G 폴더폰 포함)으로 전화가 걸려와,
AI 에이전트와 통화하며 주문하고 본인의 질환·복용약·알레르기에 맞는 메뉴를 추천받는 배리어프리 키오스크 보조 서비스입니다.
팀 그랜토리가 해커톤에서 서비스 전체(키오스크 화면 · 전화 주문 흐름 · 사용자 정보 등록 사이트 · 추천 엔진)를 함께 만들었습니다.

| 구분 | 담당 |
|---|---|
| **DA — 건강 추천 엔진 데이터셋 설계 · 규칙 적용 로직** | **본인** (이 저장소) |

이 저장소는 그중 **본인이 맡은 DA 파트**만 담고 있습니다.

---

## 이게 뭔가요

키오스크 앞의 고령 사용자가 **본인의 질환·복용약·알레르기**에 맞춰
"지금 이 화면에서 뭘 고르면 좋은지"를 안내받도록 하는 것이 목표입니다.
이 저장소는 그 판단의 **근거가 되는 규칙 데이터**와, 규칙이 실제로
동작하는지 보여주는 **작은 파이썬 데모**로 구성됩니다.

핵심 파이프라인은 3단계입니다.

1. **하드 필터** — 알레르기 등 절대 안 되는 항목을 후보에서 완전히 제외
2. **건강 필터** — 질환·약물–식품 상호작용 규칙에 걸리는 메뉴를 감점(뒤로)
3. **추천 + 이유** — 남은 후보를 점수순으로 정렬하고, *왜* 주의/추천인지 문구로 설명

> ⚠️ 이 프로젝트는 **의료기기가 아니며 진단·처방을 하지 않습니다.**
> 공개된 식이 가이드라인에 근거한 **'주의 안내'만** 제공합니다.

## 데이터셋 개요

원본은 22개 시트로 구성된 `data/foodcourt_dataset_v4_3.xlsx` 입니다.
질환 선정 → 식품/영양소 규칙 → 약물 상호작용 → 메뉴 매핑 → 복합질환 충돌
→ 예외 처리까지, 근거 기반으로 직접 설계했습니다.

주요 시트:

| 시트 | 내용 |
| --- | --- |
| `01_질환선정` | 65세 이상 유병률·식이개입 명확성 기준으로 8개 질환 선정 |
| `02_질환_식품규칙` | 질환별 제한/권장 식품군 + 근거수준(HIGH/MEDIUM) + 서비스 문구 |
| `07_질환_영양소규칙` | 나트륨·칼륨·퓨린 등 영양소 단위 규칙 |
| `08_약물_식품규칙` | 와파린-비타민K, 자몽-CYP3A4 등 약물–식품 상호작용 |
| `14_약물사전` | 약물군·대표성분·국내 제품명 매핑 |
| `15_메뉴사전` | 메뉴별 food_tag·연결 질환·연결 약물 |
| `16_복합질환_충돌` | 고혈압+CKD 칼륨 충돌 등, 규칙이 상충할 때의 해소 원칙 |
| `22_닭강정매핑` | 해커톤 대상 매장(chicken-store)에의 신호 매핑 |

### 질환 선정 논리 (요약)

단순히 유병률이 높은 질환이 아니라, **"메뉴 수준에서 식이 개입이 명확한가"**를
기준으로 골랐습니다. 예를 들어 골관절염은 노인 다빈도 질환이지만 특정 음식
하나를 "피하라"고 매핑할 근거가 약해 자동 경고에서 제외했고, 반대로 통풍은
유병률 상위 10위 밖이지만 고퓨린·알코올 제한 근거가 명확해 **보조 핵심**으로
포함했습니다.

### 복합질환 충돌 처리

여러 규칙이 상충할 수 있습니다. 대표적으로 **고혈압은 채소·과일(칼륨)을 권장**하지만
**CKD+고칼륨혈증에서는 칼륨을 제한**해야 합니다. 이 경우 검사·의료진 설정이 있을
때만 칼륨 제한을 적용하고, 없으면 자동 제한을 **보류**합니다
(`16_복합질환_충돌` 참조). "확실하지 않으면 임의로 제한하지 않는다"가 원칙입니다.

## 데모 실행

```bash
python3 recommend.py
```

`recommend.py` 하단의 3가지 데모 프로필에 대해 필터링 결과를 출력합니다.
실제 출력은 [`demo_output.txt`](./demo_output.txt) 참고.

핵심 동작 예시:

- **자몽에이드** → 당뇨(당) + 암로디핀(자몽–CYP3A4 상호작용) **이중 감점**
- **김치찌개·라면·설렁탕** → 고혈압 나트륨 규칙으로 감점
- **된장찌개** → 대두 알레르기로 **하드 제외**
- **시금치나물** (와파린 복용 시) → 비타민K 주의 문구 (금지가 아니라 "양 일정 유지")
- **고혈압+CKD** (검사 미확인) → 칼륨 제한은 **보류**, 나트륨 규칙만 적용

프로필을 바꿔 보려면:

```python
from recommend import Profile, print_report

print_report(Profile(
    diseases=["통풍", "이상지질혈증"],
    drug_ids=["RX001"],        # 와파린
    allergen_tags=["PEANUT"],  # 땅콩
    ckd_lab_confirmed=False,   # CKD 조건부 규칙 on/off
))
```

### 점수 로직 (요약)

- 기본 10점에서 시작
- 하드 필터(알레르기)에 걸리면 후보에서 **완전 제외**
- 질환 LIMIT 규칙: 근거수준 HIGH −5 / MEDIUM −3 (**질환당 1회 캡**)
- 질환 RECOMMEND 규칙: HIGH +3 / MEDIUM +2
- 약물 상호작용: HIGH −6 / MEDIUM −3 (**약당 1회 캡**)
- CKD 등 조건부 제한은 검사·의료진 확인(`ckd_lab_confirmed=True`)이 있을 때만 적용

## 한계 및 참고

- **규칙–메뉴 매칭은 메뉴명 키워드 + food_tag 하이브리드 방식**입니다.
  메뉴명이 규칙 키워드와 정확히 겹치지 않는 일부 경우(예: 국물류에 정제곡물
  규칙의 문구가 붙는 등) 사유 문구가 다소 부정확할 수 있습니다. 이는 로직의
  한계라기보다 **메뉴별 food_tag 정밀 검수의 규모 문제**로, 실제 서비스에서는
  메뉴 사전의 태그를 사람이 검수하고 옵션(소스 적게 등)까지 반영해야 합니다.
- 점수·가중치는 데모용 값입니다. 실제 서비스에서는 질환·약물별 임상 우선순위와
  근거수준에 따라 재보정이 필요합니다.
- 이 저장소에는 해커톤 주최 측이 제공한 시뮬레이터 킷·창업팀 배포 자료는
  포함하지 않으며, **직접 설계한 데이터셋과 적용 로직만** 담았습니다.
